Scoring guide

How Colophon scores AI contribution and human review. Each category below explains what it covers, what to look at, and what each score looks like in practice.

Contribution scale Categories Edge cases Human review Scoring rules

The contribution scale

Each of the four categories gets one score for the chosen scope, such as a pull request or a release.

The four categories

Score each category separately, and count a contribution in every category it materially affected. If AI writes a function and its docstring, the function counts under Implementation and the docstring under Comments & docs.

Edge cases

Editor completions
Completions inside code you were writing are discrete pieces, usually a 2 under Implementation. When completions wrote whole functions or most of the logic, treat them as a substantial part of the result.
Spec, then agent
A specification you wrote is human work. If it fixed the design, AI contributed little to Design, even when an agent then wrote all the code, which is usually a 4 under Implementation.
AI code review
Findings from an AI reviewer count under Tests & checks. They never count as human review.
Debugging
AI diagnosing a failure counts under Tests & checks. The fix counts under Implementation.
Commit messages and PR descriptions
Count under Comments & docs.
Translations and UI text
Documentation translations count under Comments & docs. Strings shipped in the product count under Implementation.
Generated data
Test fixtures count under Tests & checks. Production data and configuration count under Implementation.
Mechanical refactors
Codemods and renames done by AI count under Implementation. A large mechanical change used as delivered is a 4; say in the disclosure that it was mechanical.
Team changes
Ask the contributors. If you cannot establish a category’s score, use ?.

Human review

How much AI contributed and whether a person checked it are separate questions. Any contribution level can have Full review, and authors may review their own work as long as they deliberately check it against relevant criteria.

A check means a person read and understood the contribution and verified it, for example by running the tests or comparing the docs with the code. Skimming is not a check, and an AI review on its own is not human review. Say in your disclosure whether the review was the author’s own or independent.

The last cell of the badge flags the review status: a green check for Full, an amber exclamation mark for Partial, and a red cross for None and ?. Unlike the contribution scores, this marker is a deliberate warning: code that nobody checked is a risk, whoever wrote it.

Scoring rules

  • Count every AI use you know of, including always-on editor completions, chat advice, and agents.
  • Use 0 only when you can confirm that AI was not used, and – when the scope has no work in that category. When you cannot establish a score, ? is a legitimate answer.
  • If parts of the scope differ, score the highest level that applies to a material part, and name that part in your disclosure.
  • A person determines the result through material specifications given before the draft or changes made after it. Formatting, small wording fixes, and approval alone leave a substantial AI contribution at 4.
  • Choose 4 if substantial AI output was used largely as delivered, even when it was fully reviewed.
  • If every score is 0 or –, assess the review of the final change itself.
  • If any score is unknown, choose Full only when the review covered all work in scope.
